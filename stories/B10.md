## Outcome

Deliver a bounded plugin interface and one MCP integration. Deliver observable behavior in small reviewable slices.

## Prerequisites

B02, B04, B05. Guest implementation requires the recorded owner continuation.

## Commit-sized execution slices

Start from a verified checkpoint, mark in_progress only when implementation starts,
and regenerate progress. Each numbered slice can produce several small commits;
commit a working boundary without waiting for the entire story. Keep each diff
focused and save next command/log/checkpoint before stopping.

1. Define versioned manifests, capabilities, schemas, provenance and separate process/credential boundaries.
2. Implement one replaceable MCP adapter and an actual local test server integration without a cloud account.
3. Apply timeouts, output limits and explicit per-plugin grants; discovery/install/update cannot inherit administrative policy.
4. Test one successful call, timeout, removal/revocation and credential separation.
5. Keep email/calendar/cloud optional and outside the first-preview mandatory integration set.

Additional harness slice: Implement the documented minimum on-demand SKILL.md contract, user skill editing/import and versioned isolated extension hooks; importing resources never executes helpers.

## Review-critical execution details

- Prove a real process/filesystem/IPC/network containment boundary with dummy secrets; a different PID under the same UID alone is insufficient.
- Implement one opt-in browser bridge against a harmless local page and isolated test profile; page text remains untrusted and Stop/error use the same task boundary.

## Acceptance criteria

- [ ] Versioned plugin schemas and one actual local MCP integration work end to end with timeouts and separate credentials.
- [ ] Removal/revocation blocks further calls; plugin discovery/install/update grants no implicit account access or administrative privileges.
- [ ] One focused capability-denial and isolation check passes; optional external connectors are honestly unverified or disabled.

- [ ] One user skill loads only when relevant; unknown code/hooks stay disabled and skill instructions cannot override executor policy.

- [ ] One opt-in browser tool navigates/reads a harmless local page with an isolated test profile, explicit Stop/error behavior and no authority inherited from page content.
