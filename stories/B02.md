## Outcome

Deliver the minimal branded GNOME desktop. Deliver observable behavior in small reviewable slices.

## Prerequisites

B01. Guest implementation requires the recorded owner continuation.

## Commit-sized execution slices

Start from a verified checkpoint, mark in_progress only when implementation starts,
and regenerate progress. Each numbered slice can produce several small commits;
commit a working boundary without waiting for the entire story. Keep each diff
focused and save next command/log/checkpoint before stopping.

1. Build pinned graphics, input, display/login, network and audio dependencies incrementally; checkpoint the first working graphical session.
2. Package one browser, file manager, terminal, simple editor, settings and required accessibility components; avoid the full GNOME app collection.
3. Apply supported desktop settings, launcher layout and provisional navy background without forking GNOME or globally overriding unrelated app CSS.
4. Prepare optional OpenCode/VS Code package definitions; review exact binary/license/update paths and show unavailable rather than inventing support.
5. Run one basic desktop pass, capture boot/idle measurements and prove normal use with the agent and inference stopped.

## Review-critical execution details

- Use Bash/native terminal navy defaults; optional Starship/tool hooks respect user edits and interactive shells. Do not force a font, shell framework or extra CLI package into the base.

- Follow docs/PHASE-2-READINESS-REVIEW.md for actual native interaction, affected visual states, text/scale handling and bounded rendering; concept screenshots alone do not validate this graphical slice.

- Apply docs/PHASE-2-CRITICAL-PATH.md: measure runner overhead, distinguish build/live/offline/acquisition package roots and reuse qualified probe packages; prioritize the measured longest eligible branch without bypassing prerequisites.

- Review ABI compatibility and security exposure of new browser, XML, network and privileged consumers before packaging; preserve the frozen foundation unless an explicit affected-update decision is recorded.

## Acceptance criteria

- [ ] Login and basic browser/files/terminal/editor/network/audio work in the reference guest using pinned owned packages.
- [ ] The desktop stays usable without keys, models, network or active agent/inference; optional network applications fail clearly.
- [ ] Publish the minimal package manifest, resource measurements and optional-app packaging status; no unsupported package is advertised as working.

- [ ] New browser/XML/network/privileged consumers have recorded security/ABI review and owned pinned dependencies; no silent frozen-foundation upgrade bypasses a failure.
