## Outcome

Persist tasks and recover interrupted system changes. Deliver observable behavior in small reviewable slices.

## Prerequisites

B04. Guest implementation requires the recorded owner continuation.

## Commit-sized execution slices

Start from a verified checkpoint, mark in_progress only when implementation starts,
and regenerate progress. Each numbered slice can produce several small commits;
commit a working boundary without waiting for the entire story. Keep each diff
focused and save next command/log/checkpoint before stopping.

1. Persist intent, lifecycle, selected model/provider, policy reference, operation IDs, results and verified completion.
2. Bound retries, deadlines, context/output and managed subprocess lifetime; Stop must not depend on model compliance.
3. On restart reconcile a known effect using its postcondition; uncertain operations enter review rather than automatic replay.
4. Version non-secret desired configuration separately from one-off changes; report drift without repeatedly undoing deliberate user edits.
5. Demonstrate one restart, one Stop/revoke during work and restoration of one deliberately broken guest configuration.

Additional harness slice: Implement atomic schema-validated profile revisions, last-known-good recovery and task revision pinning before exposing editable settings.

## Acceptance criteria

- [ ] Tasks survive a service restart without duplicating a known side effect; uncertain outcomes wait for review and retries remain bounded.
- [ ] Stop prevents queued/new actions and terminates or reports active managed processes; revoke immediately blocks new privileged dispatch.
- [ ] One configuration rollback restores service operation, preserves a manual rescue path and reports drift without fighting user intent.

- [ ] Invalid profile configuration preserves the working revision; one rollback and task-revision pinning check pass without unexpected replay.
