## Outcome

Freeze the minimal Toddy architecture and delivery slices. Deliver observable behavior in small reviewable slices.

## Prerequisites

## Commit-sized execution slices

Start from a verified checkpoint, mark in_progress only when implementation starts,
and regenerate progress. Each numbered slice can produce several small commits;
commit a working boundary without waiting for the entire story. Keep each diff
focused and save next command/log/checkpoint before stopping.

1. Inventory the accepted foundation checkpoint and disposable reference VM; do not rebuild accepted packages.
2. Resolve exact GNOME/GTK4/Libadwaita, Pi Agent Core/Pi AI and runtime versions from upstream; inventory transitive licenses, package names and build inputs.
3. Run one minimal engine/provider/tool spike with a deterministic fixture. Compare one alternative only if a concrete compatibility, license or resource blocker is found.
4. Freeze the minimal desktop application manifest, optional OpenCode/VS Code packaging candidates and hardware/third-party pack policy.
5. Measure the initial reference baseline, adopt or justify revisions to the provisional performance targets, and record exact next independently reviewable slices.

Additional harness slice: Freeze versioned per-user harness/profile/schema and minimum SKILL.md contracts using Hermes/OpenClaw patterns; add one secret-free profile fixture.
