# Phase 2 development blockers: 2026-11-18 audit

Scope: local MVP graphical preview and its path to the accepted installed release. This is an execution audit, not B06/G2 acceptance. The Candidate VM is cold; both candidate qcow2 files passed `qemu-img check` after the read-only probes.

## Execution update on 2026-11-18

The Candidate VM was started after this read-only audit. Installer7, projection4, signed export6 and fresh inputs2 passed. Generation3's uncertain root was archived with full host readback before retirement. Generation4 then unpacked but stopped at the HWDB native cache command; its root and write-once failure record remain. A disposable matrix found five cache byte divergences. The five-cache/installer8 route is in source review, and host space is below the conservative admission for archiving generation4. See [generation4 evidence](evidence/B06-generation4.md) and [process improvements](PHASE-2-PROCESS-IMPROVEMENTS-2026-11-18.md). Historical recommendations below describe the original audit and are superseded by this actual update where they differ.

## Bounded resumption gate

1. Finish the package-cache provenance decision and affected source/tests, then regenerate the exact installer/package/projection/export/image inputs in new immutable names. Validate source coherence at every boundary; do not reuse installer6 or export5 as if they contained changed bytes.
2. Measure storage for generation 4 and the next media stage. If insufficient, archive one fixed failed root with full independent proof before retirement. Preserve the other failed root and every journal.
3. Sync committed source into the Candidate guest, confirm no writer and generation 4 absent, then unpack once. Before qualification, verify selected package cache bytes/metadata and complete input namespace. On failure, use the recorded first failing command and stop; on success, require zero blockers and a real candidate receipt.
4. Apply the same-inode production finalizer and boot/install smoke only after independent reviewed-input proof. Record commands, exit status, elapsed time, hashes, root identity and artifacts. No deferred check is marked passed.
