# ADR0154: DConf local source fallback and generated runtime cache

Status: qualified and owned, 2026-11-09.

Frozen BLFS13.1 DConf0.49.0 contains the GVDB source pinned in its wrap. The own
nofallback option refused that supported local dependency. Enable nodownload
fallback with its exact immutable local source; compiler network remains absent.
All15bundled files match official GVDB commit4758f6fb7f889e074e13df3f914328f3eecb1fd3.
No runtime API/source change or moving Git revision is used. The initial
unnecessary duplicate extraction was verified byte-for-byte and only that new
copy removed while finishing the known preparation receipt; no uncertain replay.

Run all14DConf runtime/ABI programs and two GVDB original programs in a private
D-Bus session. Optional shellcheck lint and DConf Editor are outside the selected
runtime profile, not claimed passes. Actual CLI typed values, malformed-input
refusal, new-bus persistence/recovery/reset and actual GSettings DConf backend
write/sync/persistence/reset passed. Staged GSettings verification reused existing
compiled/staged/source-suite evidence. Initial inaccessible /opt probe dispatch
failed before execution; exact versioned python3 -c dispatch passed.

The first native GIO module cache is generated by the qualified installed
/usr/bin/gio-querymodules inside the full-root transaction. Record input/output
hashes and generated path separately from archive payload. Recompute only when
qualified module inputs change; do not package a stale shared cache or change
user configuration. Current native directory contains only libdconfsettings.so.
CLI/backend probes use private schema and user database, never the owner's keys.

[Owned package evidence](../evidence/B02-dconf-install.json) records install/post0/0,
original16programs0 and installed actual CLI/GSettings/audit0. This does not qualify
a GNOME login/settings UI, full desktop, or physical hardware.
