# ADR-0252: Owner resumes the plan and requires standard Git delivery

Date: 2026-11-20, America/Sao_Paulo
Status: Accepted by explicit owner instruction

After the generation8 bounded cut was closed with preserved compression-gate
failure evidence, the owner requested the next phase, then instructed the agent
to continue until development of the existing plan is finished. The owner also
explicitly required commits, pushes and integration into main through the
project's standard Git flow. This resumes the already approved Phase2 plan;
it does not convert unexecuted runtime tests or physical validation into passes.

Continue B06 first, resolve the observer procedure with a disposable overlay,
then follow actual story dependencies through the existing B01–B13/G2 contract.
The earlier restriction against B07–B13 progression applied to the now-closed
single generation8 cut. The latest autonomous plan-completion instruction
supersedes that scope restriction for subsequent eligible work. Keep each new
slice bounded, independently reviewable and truthfully checkpointed.

The current local ISO slice may use one fresh unique generation9 only after
source/input identity and measured capacity admission. Preserve generation8 and
historical6/7 evidence. Verified complete private host custody may replace only
the designated failed expanded root's guest copy to recover space; original
receipts/guards and accepted images/backings remain. Never replay generation8
compression, refresh its original manifest, or start a second guest writer.
If a new generation/media result fails or becomes uncertain, stop that bounded
attempt without another generation; follow the existing failure ledger and
30-minute/two-correction rule. Independent eligible source work may continue.

Use topic branches and PRs with required checks before main integration. The
observed main ruleset requires squash, linear history, check/public-content and
one CODEOWNER approval. The connected markaraujo identity is also PR2's author
and sole configured CODEOWNER; GitHub rejected the owner-requested self-approval
with `Can not approve your own pull request`. Authorization to deliver does not
satisfy that platform requirement. Do not bypass or weaken the ruleset or
impersonate a reviewer. Preserve the concrete approval dependency while doing
useful development on branches; merge only when the platform requirements pass.

No instruction guarantees uninterrupted runtime or unlimited usage. Preserve
source/VM/job/receipt checkpoints across restarts. Guest implementation, genuine
ISO boot/installation evidence, protected-main delivery and owner physical
validation remain distinct observations.
