Date: 2026-11-05. Result: all H03 criteria passed in the KVM build guest.

## Guarded target preparation

scripts/build/prepare-target.sh first ran without --apply, returning 0 and
printing the disk plan without changing the disk. A subsequent lsblk showed
only a blank vdb with no filesystem or partitions. Guard checks verify guest
hostname, actual virtualization, root disk identity, target serial, exact
capacity and the intended mount. Only /dev/vdb with serial TODDY-LFS-TARGET
is accepted; workstation disks are never attached to this VM.

The applied run returned 0. Result: GPT, 2 MiB BIOS boot partition, 512 MiB
FAT32 EFI partition, 8 GiB swap, and 171.5 GiB ext4 root labelled TODDY_LFS
mounted rw at /mnt/lfs from /dev/vdb4. Ownership/mode of target root:
root:root/755. No /usr/lib64 exists. The book directory layout and /bin,
/lib, /sbin symlinks were verified. An lfs user owns build directories and
has the book's clean environment, x86_64-lfs-linux-gnu target, POSIX locale,
umask 022, no command hashing and eight build jobs. Guest global bashrc
was moved aside as the book directs. No author-home path or host-native
compilation flag is in target recipes.

## Runner and negative checks

scripts/build/run_step.py validates mounted target before traversing or
executing. It locks concurrent installation, stores a running record, recipe
and postcheck hashes, log hash, exit codes and content-based file manifests.
A running record is unfinished work and prevents an automatic retry.

In the real target, h03-success returned recipe=0/postcheck=0 and recorded
/var/toddy-runner-probe in its manifest. h03-failure returned recipe=42 and
had no success marker. h03-postfailure returned recipe=0/postcheck=42 and
also had no success marker. verify-runner.sh asserted these conditions;
its overall exit was 0. The probe file was removed after testing.

An initial runner launch failed before executing because runuser was outside
the sanitized PATH. The running marker correctly remained incomplete. After
confirming no payload had been written, retained the interrupted record,
corrected the executable path and reran. See docs/errors.md.
