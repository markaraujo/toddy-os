# H09 — Production kernel and native BIOS/UEFI boot accepted

Observed 2026-11-07. H08 passed before dispatch. The production kernel,
boot-configuration and bootloader recipes each completed with recipe/postcheck
exit 0/0. The target has 129 configured native packages and an empty Dpkg audit.
Exact hashes, commands and observations: [H09-native-boot.json](H09-native-boot.json).

## Sources and artifacts

Followed frozen LFS 13.1-systemd sections 10.3/10.4, with the documented package,
generic configuration and serial-console choices in ADR-0046/0051/0078/0085.
Linux 7.1.8 was re-extracted from its hash-verified frozen archive and built with
native GCC 16.2.0 at eight jobs. All 139 requested configuration values survived.
The release is `7.1.8-toddy`; no workstation-specific `-march=native` is enabled.

The 15,553,536-byte kernel image has SHA-256
`3ccb8a6c3f3e125542e3d6892e242af1d37e873833de27ee32e3951871a723a1`.
Resolved configuration SHA-256 is
`3ad1bf1ce1e1a844ac35a5c0c9769536bff6e30d9ae75dd20ee2341a9f544e0e`.
The independently rebuilt image matches the earlier private native image;
this narrow result does not establish whole-distribution reproducibility.

GRUB uses the measured disposable root filesystem UUID and partition PARTUUID,
serial and virtual console output, and the direct-root kernel entry. Native
BIOS and removable UEFI installation passed with no firmware NVRAM writes.
Partition tables and owned boot inputs remained unchanged. Original boot
sectors and generated-file inventory are preserved outside Git.

## Actual acceptance

Both separate QEMU/KVM guests used a generic `qemu64` CPU, two CPUs, 2 GiB RAM,
no network, their own disposable writable overlay and the verified cold target
as a read-only backing image. UEFI used the pinned OVMF code and fresh variables.
Both reached native Systemd PID 1 through the installed GRUB/kernel/root path.
Each compiled and executed a libc-linked C program with no temporary-toolchain
library paths, loaded the actual dummy module through native Kmod, observed its
network interface, removed it, and powered off with QEMU exit zero.

The controller verified the backing image SHA-256 before and after each test.
Both reports reached `passed`; terminal orchestration exit is zero. Serial
logs, exact launcher invocations, source commit and report/log hashes are in
the machine-readable evidence. The probe is supplied through temporary firmware
credentials; it is not installed in the system or a distributable image.

Boot logs contain the expected absent `regulatory.db` warning: no external
wireless regulatory database/firmware was included, and Wi-Fi is not qualified.
BIOS also recorded a clocksource watchdog read timeout during shutdown; the
probe and clean power-off completed. Retain the raw warning; no global clock
or security setting was changed to suppress it.

## Recovery and limits

`h07-final-base` remains the verified pre-boot-sector recovery pair. The fresh
`h09-boot-ready` pair passed copied/source hash equality, an independent verify,
qcow2 checks and builder restart. Restore only while the builder is stopped,
using `scripts/host/checkpoint.py`; never restore a live disk. The two test
overlays and serial logs are retained under `.local/vm/boot-tests/`.

This accepts kernel/boot preparation and actual early native boot. Live ISO,
console login, DHCP/DNS, virtual USB, volatile overlay and H12's outstanding
native regression checks remain required. Physical GPUs, Wi-Fi, audio, firmware,
Secure Boot and physical installation are not qualified. H09 grants no G1 or
Phase 2 acceptance. Proceed to H10 live-system assembly.
