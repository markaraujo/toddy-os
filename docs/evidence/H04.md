## Actual target checks

- Cross tools resolve inside /mnt/lfs/tools; GCC reports target
  x86_64-lfs-linux-gnu, version 16.2.0 and sysroot /mnt/lfs.
- Generated object has x86-64 ELF architecture. Linker search paths are
  sysroot-relative (leading =), as required by the book.
- Headers define LINUX_VERSION_CODE 459016, major 7/minor 1/sublevel 8.
- C hello-world compiled and linked using target startup files, headers and
  libc, with program interpreter /lib64/ld-linux-x86-64.so.2. No RPATH/RUNPATH
  was present. Linker diagnostics found libc and loader under the target root.
- Invoking the actual target loader with only the target library search path
  ran the C executable, printing “Toddy cross libc OK”. Loader dependency
  listing resolved libc.so.6 to /mnt/lfs/usr/lib/libc.so.6.
- libstdc++ headers and shared library exist; libtool archives were removed as
  the book directs. Its NEEDED entries are libm.so.6, libc.so.6 and the loader.

The /mnt/lfs/tools prefix and these tools' build-host dependencies are
intentional temporary infrastructure. They are not release binaries.
Chapter 6/7 transitions and final chapter 8 rebuild/tests must remove those
paths from the final system. Final compiler/libc critical suites have not
run and are not waived. Known baseline security obligations remain ADR-0007.

## Failures and recovery

The first binutils attempt failed before writing installed paths because the
source transport reset directory permissions. Corrected mode and transfer
method; failed record/log preserved under guest runner history. No version
was upgraded or failure marked successful. See docs/errors.md.

A controlled source-integrity test in the actual guest changed a saved patch,
verified rejection before extraction, restored the exact original and then
verified acceptance. Log: .local/logs/guest-source-integrity-negative.log.
The patch remained identical to its frozen hash after the experiment.
