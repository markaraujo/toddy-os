# Phase 2 process improvements from the B06 failures

The current chain uses exact source hashes and immutable output names, which protected earlier evidence. Its bottleneck is that cache behavior and storage needs were discovered only after expensive package, export and root generations. Apply these changes in this order; none of them is a claim that an ISO boots.

1. **Run one disposable cache matrix before a new installer package.** From the exact selected manifest, invoke every distinct fixed cache command once in an overlay, record exit, stderr size, expected and actual SHA-256, and verify the lower root stayed unchanged. Classify all differences together. The generation4 matrix found five divergent outputs after earlier work had addressed only two. Keep exact package-owned outputs only when their archive, record, owner, mode, selected inputs and runtime behavior are independently checked. For genuinely union-derived caches, define an explicit generated-output proof instead of silently replacing expected hashes. Docker's documented cache invalidation behavior reinforces that cached layers and inputs must be pinned and deliberately rechecked; it does not itself prove Toddy's native cache semantics. [Docker cache invalidation](https://docs.docker.com/build/cache/invalidation/).
2. **Make failure telemetry part of every one-shot native command.** Record the fixed argv, output path, exit code, bounded stderr, completed commands and root identity in a write-once failure receipt. Stop immediately when an intent exists without a completion receipt. A second attempt must target a fresh generation after a disposable reproduction; stop the slice after two corrections of the same cause or 30 minutes. Generation4 now records the failing producer, but the generic native runner still discards stderr.
3. **Budget the complete chain before the first write.** Admission must include installer package, projection, export, host transfer, signatures, input bundle, one fresh root, media, and one worst-case retained failure. Check both guest and host at every boundary. Use the existing 16 GiB guest reserve and the 60 GiB local MVP host floor; never turn a low-space condition into an unsafe cleanup. Maintain a fixed, round-trip verified archival route for uncertain roots.
4. **Reduce manual generation wiring.** A single reviewed generation manifest should list installer version, projection, signed export, inputs, candidate root, reviewed root and media paths, with source and package hashes. Generate fixed wrappers and consistency tests from that manifest. Do not dynamically select arbitrary paths at runtime. The repeated edits from installer7/export6 to installer8/export7 show why this is valuable.
5. **Separate proof from acceptance.** Each gate should emit machine-readable input and output hashes, tool identity, exact command, and result. A package/export receipt establishes provenance; B06 still needs a candidate with zero blockers, independent reviewed inputs, finalizer, boot and installation evidence. SLSA defines provenance as the verifiable trail of where, when and how artifacts were produced; it is separate from a claim that the product works. [SLSA provenance](https://slsa.dev/spec/v1.2/provenance/). Reproducible Builds defines byte-for-byte reproducibility against declared source, environment and instructions; Toddy should claim it only after an independent matching rebuild. [Reproducible Builds definition](https://reproducible-builds.org/docs/definition/).
6. **Use review gates for repository changes.** The current pushes reported bypass of protected `main` and two expected checks. Move future package/boot changes through a small branch and PR with the relevant tests and required status checks; keep the one active native VM coordinator outside CI. GitHub documents protected branches as the mechanism for required reviews and checks. [GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches). Artifact attestations can later bind distributable files to a workflow and commit, but they do not replace native boot/install tests. [GitHub artifact attestations](https://docs.github.com/en/actions/concepts/security/artifact-attestations).

The immediate next run is bounded: finish the fixed package8/export7 route, verify host capacity, archive generation4 after complete proof, create generation5 once, and stop on any new resource failure. No earlier root is retried.
