# Actual native acquisition full-flow qualification

This is an execution/report-input contract, not completed qualification. The new
read-only source assembler never installs, upgrades, removes, signs, prompts,
creates receipts or publishes. No runtime/package manifest changed. All native
execution, owner authentication and protected receipt capture belong to the
parent's single-writer disposable installed-VM jobs. Source tests cover refusal
only and cannot supply a native-full-flow report.

For local-runtime/agent-local, exact unchanged B03 native archive/CPU profile and
component masked-CPU denial may support only LOCAL_CHECKS. They never fill the
nine required production checks above. The assembler consumes the genuinely
signed component report/evidence and strict concrete CPU receipt for those local
facts; their exact package/code/trust pins must match. Existing B03 inference and
B05 recovery remain scoped evidence, never a new acquisition/full-flow pass.

`require_full_flow()` requires all advertised entries to have actual full-flow
reports, with agent-backend+local-runtime or agent-local coverage. It does not
let one case/report qualify another release ID/package set. Keep unsupported
entries unavailable until their own matching proof exists. The final publisher
still runs the existing independent-public-pin guard and all other G2/ISO gates.

## Concrete lifecycle prerequisite

The production helper actions remain install/status/cancel/reconcile. Existing
version mismatch is refused and native install uses no-remove. Do not invent
upgrade/remove arguments, edit production code, replay an old install, pass an
allow-downgrade shortcut or fabricate an installed version to satisfy lifecycle.

The parent must build an actual allowed project packaging revision2 from the
same frozen runtime/upstream/code, with truthful native record and original
copyright/source notices, and sign a real Packages/Release containing that exact
second archive. Prefer toddy-agent in a combined/backend run so the package being
removed is not the running privileged executor. A local-runtime-only run needs
its own real corresponding package revision2; the primary frozen B03 declaration
and runtime archive remain revision1. This source creates neither archive nor
signature. Package documentation/version indexes may change; runtime/executable/
unit/non-documentation payload, copyright, source set and control fields except
Version/Installed-Size must remain identical. A changed runtime is a new scope.

Use the existing separate explicit owner administration/executor package path or
explicitly authenticated native administrator, stop dispatch and services at the
safe boundary before modifying code, and retain actual native upgrade/remove
exits and postconditions. The second archive must genuinely reach version2.
Remove it explicitly, preserve private state, restore the original source/trust
and primary declared set by a NEW explicit Setup install with fresh unchecked
terms and a new operation ID, then reopen the actual Setup UI and verify
packages_present. No old success/duplicate/downgrade is a reinstall proof.
Retain independent native package recovery observations and unchanged private
state hashes, no automatic activation, and fresh actual UI capture.

The protected artifact directory is
`/var/lib/toddy/native-acquisition-full-flow-1/lifecycle-artifact2`. It contains:

- artifact.json with exact name, version, architecture, record, archive,
  primary_record and primary_archive. Both filenames use actual canonical native
  NAME_VERSION_ARCH.json/.deb; the versions must differ and version2 be greater.
- Both actual native archive/record pairs, exact primary archive matching the
  declared SHA and the real signed second archive; no synthetic fixture package.
- Only the public archive-keyring.gpg plus actual second Release/Release.gpg and
  Packages. Independent primary key hash/fingerprint must match the tested
  release. Never copy a signer home/private key into this directory or guest.

The assembler re-parses actual archive/control/payload/legal ownership, verifies
record/archive signatures/index bindings, version ordering, frozen runtime/source
invariants and actual lifecycle observations. Missing artifact2 is a hard failure.
Old custom executor fixture archives, source receipts or package status strings
are not alternatives.

## Actual protected case receipts

Use separate fresh disposable installed overlays where a case needs an absent
agent/offline/Stop state. Retain actual boot/root/overlay identities and full native
job source, execution exits and postconditions. Only the initial install and its
separate lifecycle run may share an already installed baseline. No private
password/PAM tty, provider credentials, keyring values, signing material or model
prompts belong in receipts. Record nonsecret helper results/canonical observations
and native GTK screenshots through existing parent-owned capture jobs; do not
hand-fill these fields from expected outcomes. No generic verified callback or
marker is accepted by the report assembler.

The fixed context contains install.json, stop.json, reconnect.json, tamper.json,
offline.json and lifecycle.json. Each has exactly:

```text
version: 1
kind: actual-production-acquisition-full-flow-case-v1
case: one fixed case name
environment: native-installed-user
fixture_only: false
bindings: exact release_id/tested_preview_catalog_sha256/package_set_sha256/code_pins/trust_pins
owner_uid: actual authenticated installed owner
session: actual loginctl User/Active/Remote/LockedHint/Type/Class/State/Service properties
boot_id, root_uuid: actual case guest identities
runner_exit, postconditions_exit: actual integer zero exits
artifacts: execution/postconditions/ui_capture filename+SHA256 bindings
observations: execution/postconditions actual parsed observations
```

Session properties must identify that UID, active/unlocked/local Wayland user
class and actual installed gdm-password login; a source headless GTK fixture or
old root-created tty session is not this full-flow UI proof.

Bindings come from the actual verified signed preview catalog and installed
assistant source-manifest, not a manifest's claim. Each case has protected
CASE-execution.json, CASE-postconditions.json and CASE-ui_capture.png. The JSON
artifacts bind the same case/owner/pins and their actual observations; screenshots
are actual native GTK captures for that case. Files/directories must be root-owned
and nonwritable by others, physical/nonhardlinked, with complete hashes. A case
summary differing from its retained execution/postcondition artifacts is refused.
Component report shape/renamed levels/check booleans cannot be loaded as cases.

The exact semantic observation fields are enforced in the source assembler:

- Install result identifies fixed helper/current helper SHA, authenticated UID,
  real operation/journal ID+installed state, actual complete preinstall inventory
  with every reviewed package absent, one production dispatch/native write, and
  actual complete installed version inventory/vital-path hashes. UI/PAM/unchecked consent observations identify GTK4/app/action.
  Before/after services have user_agent/root_executor/local_runtime entries with
  inactive/not-loaded/not-running states. Sensitive root_grant/provider_connections/
  keyring_metadata/model_metadata are metadata hashes or absent; root grant is
  absent and metadata unchanged. Do not read/export key contents.
- Stop retains actual authenticated cancel acknowledgement and released UI busy
  state. boundary=before_write requires canceled terminal/no write intent and
  unchanged complete inventory/Dpkg SHA. boundary=after_completed_write instead
  requires actual installed state, one write, exact declared inventory/vital
  hashes and explicitly preserved committed effects. Neither path kills Dpkg,
  replays an operation or claims committed effects were undone.
- Reconnect retains actual authorizing/outcome_unknown private cursor after lost
  reply/native write (process death can preserve the earlier durable authorizing
  state), new install blocked before reconcile, explicit reconcile, same operation before/after, exactly one install submission
  and native write, identical package-state digest after write/readback and actual
  UI installed state. Never kill healthy Dpkg; lose the controller/reply only.
- Tamper retains actual consumer reason/unavailable state, exact restored original
  hash, zero root submissions and unchanged actual journal/Dpkg digests.
- Offline retains actual authenticated helper deferred/no-write-intent state,
  actual network/fixed-repository unavailability, responsive deferred UI, unchanged
  complete inventory/Dpkg and zero automatic retries.
- Lifecycle retains the separate explicit authority, actual upgrade/remove exits,
  signed artifact2 name/version/SHA, actual version2 then removal absence,
  preserved private-state digest, new production-helper reinstall result and
  original exact closure, new operation distinct from initial install, actual
  packages_present UI and zero automatic activations.

These are actual execution/postcondition inputs from trusted native jobs, not a
blank form granting permission or success. If the existing native harness cannot
capture a required observation, record that concrete blocker and do not assemble
or publish a full-flow claim. No native case has been run by these source tests.

## Read-only assembly and independent publication

Create the root-owned nonwritable disposable safety marker
`/etc/toddy/native-acquisition-full-flow.json` with exact version1,
scope=native-acquisition-full-flow, disposable=true, actual owner_uid and actual
root_uuid. It is only a target guard; it cannot replace receipts or qualification.
The assembler independently requires root, installed ID=toddy/nonlive, QEMU/KVM,
matching actual root UUID and active local unlocked installed owner. The installed
native metadata must still be the exact signed component preview under test.

After all actual cases/artifact2 exist:

```sh
set -o noclobber
/usr/bin/python3 -I /opt/toddy-build/scripts/qualification/native_acquisition_full_flow.py agent-local \
  > /var/lib/toddy/native-acquisition-full-flow-1/assembled-result.json
```

Choose only the actually tested release ID. The program writes no file, runs no
package operation and creates no signature/catalog; output redirection belongs
to the parent's explicit new artifact. Refusal is a failure, never a passed
receipt. It emits evidence+qualification only after every required protected case,
actual signed artifact2 and local supporting evidence passes strict validation.
The parent must retain `retained_evidence` using canonical pending._encode plus
one newline; its SHA must exactly equal qualification.retained_evidence_sha256.
Retain qualification with its own hash, independently review actual logs/captures,
then separately sign/seal the final catalog. Keep tested preview catalog revision
as historical input, not as the final catalog's recursively changing hash.

The existing final publication guard still requires actual native-full-flow,
exact package/code/trust pins and supported release coverage. This assembler
cannot replace any missing native case, installer/boot proof, physical-owner test
or release-to-portal handoff, and does not mark B06/B12/G2 accepted.
